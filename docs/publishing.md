# Public repository preparation

Publish source, tests, build scripts and documentation through Git. Do not upload a ZIP of the entire development directory: that includes local state even when `.gitignore` excludes it from Git.

## Local privacy audit, October 10, 2026

A text-pattern audit found no recognizable API tokens, passwords, private keys or hardcoded IPv4 addresses in the source/documentation intended for publication. No runtime network client or embedded external-service credentials were found in the current native source. This is a review of the current working files, not a guarantee against all possible secrets or a review of remote commit history.

The local checkout was not initialized as a Git repository when audited. A read-only GitHub API check found `AbdulBasithMohammed/MinimaDock` public and empty, with no license. The commits endpoint reported an empty repository. There was no remote commit history to scan at this point. Git's ignore rules were checked using a separate disposable metadata directory under the ignored build folder: 64 files remained eligible for publication, with zero recognizable secret-pattern matches in their text contents.

Keep these existing ignored directories private:

- `recovery-bundle/`: Windows user identity, session, shell configuration, monitor state and recovery journals. Preserve this locally; it is needed for recovery.
- `captures/`: diagnostic exports can contain process paths, installed apps and window titles. Screenshots can expose desktop content if added later.
- `out/`: deployment records, local paths, account-specific taskbar journals and generated executables.
- `build/` and `.tools/`: generated binaries, diagnostics and downloaded toolchains. Release artifacts require their own review and applicable dependency notices.

Documentation examples use a placeholder checkout path. `.gitignore` also excludes local environment files, signing keys, dumps, logs and editor/agent state. Example environment files are explicitly allowed; they must contain placeholders only.

## Before the first public push

1. Review `git status --short`, `git diff --cached --name-only` and `git diff --cached`. Stage only reviewed source, tests, scripts, docs and assets. Never force-add ignored machine state.
2. If there are earlier commits, review the full history. Ignore rules do not remove already tracked files or old commits. If a credential was ever exposed, revoke/rotate it first and follow GitHub's history-removal guidance.
3. Retain the root `LICENSE`: the user selected MIT, copyright 2026 AbdulBasithMohammed. Include `THIRD_PARTY_NOTICES.md` and `third_party/licenses/` with compiled releases.
4. Use the current original geometric sword SVG/native vector, generated by `tools/Generate-LauncherLogo.py` without an image input. The former Google Images reference and traced design have been removed from publishable assets/source. Old local builds, captures and a private legacy backup under the ignored build folder must stay private. Changing formats or tracing an image does not establish redistribution rights to it.
5. Check GitHub's secret scanning and push protection settings. Also review commit author name/email; they are public commit metadata.
6. Share only separately reviewed screenshots and release packages. Do not publish personal recovery bundles in releases or issue attachments.
