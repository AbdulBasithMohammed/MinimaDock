# Temporary taskbar testing

On October 10, 2026, the user explicitly approved keeping Explorer running and hiding its taskbar for temporary tests, then requested full-height maximized windows. The temporary trial now also releases the hidden taskbar's bottom work-area reservation with journaled recovery. This exception is for development testing; the finished Explorer-free replacement remains the goal. This mode does not pass the original shell replacement gates.

## Deploy, keep, revert

Run as your normal desktop user, without elevation:

- `out\Deploy-Taskbar.cmd`: revert the previous test, copy the current build into a new retained deployment directory, verify the copy, and start a ten-minute trial.
- `out\Keep-Taskbar.cmd` or **Ctrl+Alt+K**: cancel the deadline. Crash/hang supervision remains active. Keeping never enables automatic startup.
- `out\Revert-Taskbar.cmd` or **Ctrl+Alt+Backspace**: restore captured Windows taskbar visibility and close the dock.

Right-click the pill for Keep/Revert. Quick settings includes Revert. The external launcher works when the UI fails. From Task Manager > Run new task, without administrative privileges, replace `C:\Path\To\MinimaDock` with your actual checkout path:

```text
"C:\Path\To\MinimaDock\out\Revert-Taskbar.cmd"
```

For subsequent changes, revert, edit, run `tools\Build-Portable.ps1`, validate, run `tools\Package.ps1`, then deploy again. Deploy uses the packaged binaries in `out`, allowing the last tested package to remain available while a new build is under development. Deploy reverts the previous test before starting a new one. Builds never replace running deployments. Keep `out\active-taskbar-test.json` and its referenced directory in `out\deployments`; these contain the supervisor and visibility recovery journal. Old deployments are deliberately retained.

The original shell recovery bundle remains at `recovery-bundle`. Its `Restore-Windows.cmd` handles the separate shell configuration transaction; use **Revert-Taskbar.cmd** for this visibility-only test.

Mouse press compresses only the targeted icon; resting icon size and hit areas stay unchanged. Native dock panels fade in and rise eight DIP over 180 ms; closing cancels the reveal immediately. Panel hit testing follows its visual position. Effects respect reduced motion and stop their frame timer when finished. Other applications retain Windows' own opening/restoration behavior.

Version 0.2.17 retains existing icon sides by app identity across window updates. Opening a pin adds its running indicator without rearranging any expanded slots when the existing counts remain balanced. If an update requires rebalancing, the layout moves the fewest icons possible, preferring idle pins over running apps when the number of side changes is equal. Pinned, expanded and running subsets remain balanced to within one icon; icons stay on their assigned side when hovering/collapsing.

Version 0.2.13 replaces the center Windows symbol with the user's selected crossed-swords design in bright white. Version 0.2.12 auto-hides for native snapped windows as well as maximized windows. Full-height snapped panes extend through the old taskbar reservation, preserving their exact widths, snap state and original restore placement. The supervisor reacts to snap movement/location events and retains its periodic reconciliation fallback, covering both existing panes and new snaps that use Explorer's cached work area. Quarter layouts retain their chosen geometry. Revert restores full-height snapped panes to the original work-area bottom if they are still snapped; ordinary restored windows remain visible and are not resized.

Version 0.2.11 presents popup changes atomically: new pixels, window size and position are committed together, keeping the pill anchored while Windows/quick-settings panels open or close. Popup-sized rendering resources are retained to avoid rebuilding app icons on each toggle. Native repeated-click, layout and auto-hide checks pass.

Version 0.2.10 gives both clock lines a distinct Bahnschrift Light font at 12 DIP with equal brightness, replacing the smaller/muted date treatment. Version 0.2.9 slightly enlarges Show desktop to a 14 by 26 DIP target with a longer, slightly thicker visible sliver. It retains separate space from the app icons and centered launcher. Version 0.2.8 auto-hides the whole pill for a foreground maximized app with a reversible slide/fade, slightly slower than version 0.2.7. A neutral rounded indicator, three DIP high, marks the full width of the hidden pill at the screen bottom. Hover anywhere along it to reveal immediately; leave the pill to hide. Version 0.2.6 releases the hidden taskbar's bottom reservation so maximized windows extend behind the floating pill to the bottom edge. The version-2 journal captures work areas before mutation, and standalone recovery also accepts old visibility-only journals. Monitor identity/bounds changes cancel the trial without replaying stale coordinates; conflicting work-area changes are preserved and the journal retained. Version 0.2.5 changes the taskbar and flyout glass to a darker neutral charcoal-black tint, retaining translucent depth and neutral highlights. Scale and interaction behavior remain unchanged. Native rendering was visually checked; the desktop action validation limit below remains open.

The candidate reads packaged and traditional pins in the observed Explorer FavoritesVersion 3 format through a bounded, read-only compatibility adapter. Version 0.2.1 removes the hover and exit waits. Expansion/collapse starts on the first input event, with a reversible 90 ms transition. Flyout and keyboard holds keep active controls usable. Running apps retain their side between collapsed and expanded layouts, and established app order survives foreground changes. The approved scale is unchanged. Icons use larger native shell/shortcut resources rasterized once to their physical display size, with pixel-aligned destinations. The dock renders an 88 DIP-high surface during normal use; flyouts temporarily use 440 DIP.

The primary monitor gets a transparent native Win32/Direct2D dock. Windows stays at bottom center; collapsed mode retains running/minimized apps. Hover reveals idle pins and media/system wings. Scale: 24 DIP logo, 44 DIP button, 48 DIP expanded pill. Live glass uses per-pixel transparency, gradients, edge lighting and shadows; live blur is not integrated. It does not draw the framed preview's artificial wallpaper.

Traditional pinned `.lnk` shortcuts merge with running executable identities, with running indicators and overflow menus. Store identity and exact Windows pin order are incomplete. Search uses real Start Menu shortcuts. System tiles open Settings pages; volume, media playback and third-party tray hosting are unfinished. Revert for access to the original tray. Windows key behavior remains Explorer's. The clock updates once per minute; foreground window events drive conservative fullscreen suppression. Games, multi-DPI and hotplug need broader testing.

Explorer, desktop files, Wallpaper Engine, registry and startup configuration are retained. Work areas are changed only for the active trial and restored by its supervisor/journal. Other desktop toolbar reservations are preserved. Secondary Explorer taskbars are captured/hidden too, but the custom dock is currently primary-monitor-only; actual multiple-monitor and display-change validation remains pending. Explorer can briefly redisplay its bar or reservation; the guard reconciles them every two seconds. This is a usability trial, not performance/compatibility acceptance.

## Recovery

The independent supervisor authenticates normal user/session and executable paths/creation times. Before hiding a matching taskbar or adjusting work areas, it durably records HWND, owner PID/time, original visibility, monitor identity/bounds and original/applied work areas. It refuses activation when rendering/inventory readiness fails, recovery hotkeys cannot register, or no matching taskbar exists. Deployment is single instance per user/session. No persistent shell setting changes.

The guard probes the UI thread with bounded `WM_NULL` checks every two seconds. Exit, repeated hang, deadline or explicit Revert restore visibility and remove the dock. Keep cancels only the deadline. It writes the journal only when new taskbars are discovered. Standalone Revert recovers from an absent/hung guard using this journal, validating window class, owner image, creation time, SID and session. It only terminates the identified dock and, if hung, its identified test guard. Failed verification retains the journal for retry.

The journal is parsed and size bounded but is not hardened against a malicious same-user editor. Do not move/delete an active deployment. Logoff cleanup is best effort; next sign-in uses the original desktop because startup and shell settings are unchanged.

Integration tests compile the same supervisor against mock taskbars. They cover visible/originally hidden/unrelated windows, explicit revert, dock termination, suspended UI, deadline, Keep/Revert and supervisor termination followed by journal recovery. They do not hide the real Windows taskbar. Real deployment/revert is checked separately.
